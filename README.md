# Creator Marketplace

A modular-monolith foundation for a brand and creator collaboration platform.

## Stack
- Next.js 15 App Router, TypeScript and Tailwind CSS v4
- Better Auth for identity, sessions, email/password and optional Google OAuth
- Prisma ORM 6 and PostgreSQL (Neon-compatible)
- Zod request validation

## Product account model
Public account types are **BRAND** and **CREATOR**. Modelling, UGC and other disciplines are Creator specialties—not separate account types. Staff roles (ADMIN, SUPER_ADMIN, CAMPAIGN_MANAGER, FINANCE_MANAGER) are provisioned internally and must never be exposed in public signup.

## Local setup
1. Use Node.js 20.9+.
2. Install packages: `npm install`.
3. Copy environment template: `cp .env.example .env`.
4. Configure `DATABASE_URL`, `BETTER_AUTH_URL` and a strong `BETTER_AUTH_SECRET`.
5. Configure Resend using `RESEND_API_KEY`, `RESEND_FROM_EMAIL` and `CONTACT_EMAIL`.
6. Run `npx prisma generate`.
7. Apply migrations: `npx prisma migrate dev`.
8. Start: `npm run dev`.

## Useful commands
- `npm run dev` — development server
- `npm run build` — Prisma generation and Next.js production build
- `npm run lint` — ESLint
- `npm run typecheck` — TypeScript check
- `npm run db:generate` — generate Prisma Client
- `npm run db:migrate` — create/apply a development migration
- `npm run db:deploy` — apply committed migrations in deployment
- `npm run db:studio` — Prisma Studio

## Authentication
- `/sign-up`, `/sign-in`, `/forgot-password`, `/reset-password`, `/verify-email`
- Better Auth API: `/api/auth/[...all]`
- Email verification is required for email/password sign-in.
- Password reset and verification emails use the Resend HTTP API.
- Google OAuth is optional and only shown when configured.
- The Better Auth secret must be a unique, random secret in every deployed environment. Never commit `.env`.

## Onboarding
- `/onboarding` accepts Brand or Creator details.
- Brand creation and its initial Owner membership are persisted in one transaction.
- Creator profile stores categories, specialties and languages. Modelling is a specialty.
- The API accepts only PENDING → BRAND or PENDING → CREATOR transitions. Staff roles cannot be assigned through public onboarding.
- Dashboards verify the authenticated user's role and load that user's own profile/membership server-side.

## Public pages
Home, About, For Brands, For Creators, How It Works, Managed Campaigns, Marketplace, Pricing, FAQ and Contact. Contact email delivery requires valid Resend configuration. Sitemap and robots routes are generated by Next.js.

## Current scope and honest limitations
This is a Phase 1 foundation, not a complete production marketplace. Campaign management, creator discovery, portfolios, social verification, messaging, contracts, payments, payouts, analytics and full staff administration are later phases.

Before public launch, still complete:
- Run migrations against a disposable/staging PostgreSQL database and verify the migration chain.
- Run typecheck, lint, production build and end-to-end tests.
- Add rate limiting, bot protection and abuse monitoring to auth/contact endpoints.
- Add account suspension/deletion workflows and user-facing privacy controls.
- Add audit logs and granular staff permissions.
- Configure backups, monitoring, error reporting, HTTPS and production OAuth origins.
- Review Terms and Privacy Notice with qualified Indian counsel.
- Verify Resend domain and sender configuration.

Never collect government ID, bank data, or body measurements without a documented purpose, retention policy and access controls.


## Phase 5 media uploads

Buildin uses Cloudinary signed direct uploads. Configure server-only `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` in local development and production. The API signs upload parameters after checking the authenticated user's role and ownership; the API secret is never exposed to the browser. Creator avatars and portfolio media, brand logos, campaign cover images, and creator deliverable submissions use separate folders. Current client limits are 8 MB for avatars/logos/campaign covers and 100 MB for portfolio/deliverables. Configure Cloudinary account-level upload limits as an additional safeguard. Apply the new migration with `npx prisma migrate deploy`, then run `npx prisma generate`.
